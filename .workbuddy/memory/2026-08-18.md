## go-session 技术成熟度评估 + 依赖重构

评估结论：项目处于「早期原型（~2/5）」—— 编译干净、接口抽象好，但零测试、CRLF 格式全坏、redis 有真实 bug（LastAccessedAt 恒返 1970）、gorm 强制拽入 CGo sqlite + ginkgo 等重型间接依赖。

按用户选定方案落地重构（redis 为主 + SQL 后端改用 database/sql + 纯 Go 驱动，彻底移除 gorm）：
- `redis/` 后端 import 从 `github.com/go-redis/redis/v8` 升级到 `github.com/redis/go-redis/v9`（v8 已废弃）。
- 删除 `gorm/` 目录，新建 `sqlstore/` 包（session.go + store.go），基于 `database/sql` 实现，支持 Postgres / SQLite 两种 dialect（UpsertSQL + TouchSQL 用单语句刷新 last_accessed）。并发修正：Update 在 RLock 下做快照再写库，消除原 gorm 的 TOCTOU 窗口。
- 测试驱动踩坑：`github.com/glebarez/sqlite` 自身 go.mod 依赖 `gorm.io/gorm`（连带 mattn/go-sqlite3），会重新把 gorm 拉回依赖图。改用 `modernc.org/sqlite` 直接注册 driver，gorm 彻底消失于 module graph（已 `go mod why` 验证）。
- 补 `memory/store_test.go`、`redis/store_test.go`（miniredis）、`sqlstore/store_test.go`（modernc sqlite）。
- `go build ./...` / `go vet ./...` / `go test ./...` 全绿。
- 注意：JSON 反序列化的数字为 float64，测试断言需用 float64 或字符串比较（踩过一次 `v != 42` 误报）。
